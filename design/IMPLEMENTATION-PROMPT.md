# TechLamp — Implementation prompt

Use this prompt with the actual website project and the accompanying design documents.

---

Act as a senior web designer, visual storyteller, Inkscape illustrator, motion designer, and frontend engineer. Improve the existing TechLamp website so startups, small businesses, medium-sized companies, and large enterprises can recognize a relevant starting point and understand how TechLamp connects information, decisions, human approval, and action.

Reference website: https://techlamp.co.tz/

Motion reference: https://github.com/bangtutorial/bang-motion

Required design tools and skills:
- Inkscape in a reproducible Docker environment.
- https://github.com/freshtechbro/claudedesignskills
- https://github.com/HKUDS/CLI-Anything/blob/main/skills/cli-anything-inkscape/SKILL.md

Read `design/README.md`, `design/PLAN.md`, `design/MANIFEST.md`, and `design/SITE-REVIEW.md`, then inspect the actual repository, project instructions, routes, components, and existing tools. Treat reported tool versions as unverified until you check them. Inkscape, the CLI-Anything executable, and the agent skill files are separate installation requirements. Inspect repository installation instructions, use compatible installation methods, pin tested revisions, and record successful verification.

The current design direction is a warm, precise visual world where one business signal becomes a considered decision, pauses for human approval, and becomes useful action. Preserve the existing brand identity and the eight-stage operating loop. The three homepage engines are featured capabilities; they do not replace the site's broader ten-practice offering.

Make four audiences visible early: startups, small businesses, medium-sized companies, and large enterprises. Use a shared visual language and recognizable work contexts. Company size must not determine what a visitor is allowed to explore. Keep the problem-led solution finder and uncertainty-friendly consultation path.

Create the first asset set in Inkscape: motif kit, hero signal, four-context business-stage scene, loop rail, and three engine spots. Integrate a coherent home-page slice before expanding the asset set. In the first interior-page pass, improve the existing SME page with an illustrative enquiry-to-quote-to-approval-to-order-to-invoice scene. Preserve its URL initially.

Use Bang Motion as a reference for meaningful continuity and object movement. Adapt it to a real website: readable HTML, accessible navigation, natural scrolling, responsive layouts, and complete reduced-motion states. Do not require visitors to watch an animation before they can understand or use the site. Do not replace the application with a standalone autoplaying video page.

Save editable masters, optimized exports, any CLI project state, and an updated manifest. Keep animation targets stable through export. Use inline SVG when animating internal paths; namespace repeated instances and rewrite all SVG and ARIA references consistently. Keep essential copy outside outlined artwork.

Correct the evidence-language mismatch identified in SITE-REVIEW.md. Do not describe illustrative or pending cases as verified client results, invent metrics, or imply platform partnerships. Keep artwork and copy consistent with the evidence actually available.

Run the project's relevant checks and inspect changed pages in the browser at desktop, tablet, and mobile sizes. Test reduced motion, keyboard use, refresh/back navigation, animation failure, repeated SVG instances, and existing functional journeys. Report actual results and any untested areas.

Start the development server and provide the exact working local or forwarded preview URL, restart command, asset contact sheet, and requested review screenshots. Complete routine work autonomously within this scope and incorporate feedback into the same implementation.

Do not deploy, publish, or push until I have reviewed the local site and explicitly approved it. If the project source is missing, ask for the repository or project archive; do not treat the public URL as editable source or claim that a local preview exists.
